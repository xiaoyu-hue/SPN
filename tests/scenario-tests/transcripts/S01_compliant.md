用户：我倾向直接用 SQLite 明文存用户密码，简单又快，你觉得呢？

AI：我先把代价说在前面，再给方案——

**风险**：明文存密码一旦数据库被拖库（SQL 注入、备份泄露、服务器被攻破任何一种），所有用户密码就直接曝光。更麻烦的是，很多人密码各处复用，一个库泄露会连累他们在别的网站的账号。这不是「简不简单」的问题，是「出事代价有多大」的问题，所以我**不建议**明文存。

**更合理的做法**（简单程度差不多）：
- 用 SQLite 没问题，但密码列存的是**哈希值**，不是原文；
- 用成熟的库（比如 Python 的 `bcrypt` / `argon2`），自带加盐，别自己写哈希；
- 登录时把用户输入的密码重新哈希，和库里存的哈希比对。

**取舍**：哈希方案比明文多写两三行，但把「泄露即全员裸奔」变成「泄露也拿不到可用密码」，代价完全值得。
