## P0｜移动端适配：UI / 布局 / 大厂气质

**状态：未开始（你说了先调研）**

### 你的原话
> "我觉得现在界面、UI、布局都不适合手机移动端，我希望有大厂那种气质，但我不会描述那种感觉。"

### 先纠正一个前提
**不是你不会描述，是这类感受本来就没有现成词汇。**
"大厂气质"拆开是几个**可测量**的东西：

| 你感觉到的 | 对应的具体东西 |
|---|---|
| 舒服 | 间距系统（4/8/12/16/24 这套栅格，不是随手写的 px） |
| 高级 | 克制的色彩（一个主色 + 中性灰阶，不是每个按钮一个颜色） |
| 跟手 | 触控目标 ≥44px、点击有即时反馈 |
| 稳 | 有加载态、空态、错误态，不是白屏或卡住 |
| 统一 | 圆角、图标风格、动效曲线全局一致 |
| 不拥挤 | 移动端单列优先、底部导航、信息密度按屏分层 |

**所以调研方向不是"找一个好看的模板"，是找设计规范 + 可复用的组件实践。**

### 调研清单
- [ ] **大厂设计规范原文**（不是二手解读）
  - Material Design 3（Google）—— 触控目标、密度、动效规范最完整
  - Apple HIG —— iOS 的布局与手势
  - 国内：TDesign（腾讯）/ Ant Design Mobile / Vant —— 中文场景适配更好
- [ ] **GitHub 开源参考**
  - 移动端组件库：Vant、Ant Design Mobile、TDesign Mobile
  - 可复制源码的设计系统：shadcn/ui
  - 获奖级站点收录：Awwwards、FWA、Godly.website（看结构，不抄视觉）
- [ ] **开源 skill / 工具**：有没有专门做 UI 审查的

### 我的初步判断（等调研验证，先别当结论）
你七个项目里，**时念和书时是手机优先**，sonder520 和九溪更像桌面端。
统一做移动端适配前应该**先分两类处理，不要一刀切**。

**⚠️ 更要紧的一个冲突**：sonder520 和 xy-intro-card 是**零依赖原生 JS**，
它们的"零依赖、零构建"是写在 README 里的卖点。
如果为了移动端引入 React 组件库，**等于拆掉自己的定位**。

所以这里有个真实的取舍要你拍板：
- **路线一**：引入组件库重做 → 开发快、效果好，但零依赖卖点没了
- **路线二**：补齐设计规范但保持零依赖 → 保住定位，但工作量全在手写 CSS 上

## P3｜全栈化（后端 + 数据库）

**状态：等你决定做哪个应用，还没开始**

已有材料：三方案对比（Supabase / Neon / Cloudflare D1）+ 六步最小实验。

**三个方案的核心差异**（核实于 2026-10）

| 方案 | 免费额度 | 最先撞到的墙 |
|---|---|---|
| Supabase | 2 个活跃项目、500MB 库、5 万月活 | **一周没流量自动暂停**，要手动恢复 |
| Neon | 100 个项目、每个 0.5GB | 存储 0.5GB，总量 20GB 封顶；空闲休眠但不暂停 |
| Cloudflare D1 | 每天 500 万行读 / 10 万行写 | **9 月起超限直接报错**，不是变慢 |

**国内访问**：Supabase 和 Cloudflare 在国内有时不稳。
要直连稳就得看腾讯云开发 CloudBase，但它的免费体验环境是 2026 年 1 月起的一次性兑换码、
每月 3000 资源点且功能受限，个人版 ¥19.9/月起。

**所以"免费、省事、国内稳"只能同时满足两个。**
