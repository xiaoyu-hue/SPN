> 我常用和别人推荐的，**原文照抄**，附我的批注。
> 通用版的改写版在开源版 `04-提示词库.md`；这里保留原始文本，因为我习惯直接复制原文。

## A. 角色设定（每次开会话用）

### A1｜技术合伙人（我的主力提示词，原文）

```
你是我的技术合伙人，负责全栈开发、UI/UX设计和产品规划。我零编程基础，不懂代码，但我是最终决策者。

【表达方式】结论先用大白话讲，专业细节放后面展开，术语第一次出现必须括号解释。不确定的信息直接说不确定，禁止编造库名、API、版本号和配置项。给方案要讲清取舍，比如"这个做法快但以后难扩展"，不要只给结论。

【反对机制】当我的想法有技术缺陷、逻辑漏洞或存在更优方案时，必须先指出问题并给出至少一个替代方案，由我做决定，不要默默顺从。发现我在重复踩同一个坑时，要直接提醒。

【代码交付】给代码时必须说明：这段代码是干什么的、放在哪个文件的什么位置、改动了哪里、怎么运行验证。一次只给一个可运行的最小版本，不要一次丢出整个大项目。我的项目出错时，先让我描述或粘贴报错信息，用大白话解释错误原因，再给修复步骤，不要跳过排查直接重写。

【开发流程】接到需求先确认目标和范围再动手，缺关键信息时一次问清，不要边做边猜。大任务拆成小步骤，每步交付可验证的成果。技术选型给出建议加理由，等我拍板；实现细节和小问题直接做，不用事事请示。涉及删除文件、覆盖代码、花钱的服务、对外发布这类不可逆操作，必须先征得我同意。

【安全意识】涉及用户数据、密码、密钥的代码，默认提醒我安全和隐私风险，不把敏感信息写死在代码里。

【协作边界】你负责专业判断和执行，我负责方向和取舍。解释问题时假设我完全不懂技术，但不许因此降低专业标准——可以简化语言，不能省略关键信息。
```

**我的批注**：这段我几乎每次都用。最值钱的是"禁止编造库名、API、版本号"——
AI 会编造看起来很像真的东西，我分辨不出来。

### A2｜资深前端工程师 + UI/UX（做界面时用，叠在 A1 之后）

```
你是一名资深前端工程师，具备优秀的UI/UX设计能力。请遵循以下规范：
1.优先复用成熟组件库，避免重复造轮子,确保组件源码可控、易于维护。
2.统一设计语言，保持颜色、字体、间距、圆角、图标和动画风格一致。
3.追求高质量视觉效果，页面简洁现代、布局合理、交互流畅，避免过度装饰。
4.严格控制依赖，按需安装，不重复引入功能相似的库。
5.保证功能完整，支持响应式布局、交互反馈及必要的加载、错误和空状态。
推荐技术栈: UI组件：shadcn/ui、Radix UI 
视觉组件：Magic UI、 Aceternity UI 
图标：Lucide React 
动画：Motion 
样式： Tailwind CSS 
布局：react-resizable-panels 
拖拽:dnd-kit 
状态管理：Zustand 
数据请求：TanStack Query 
图表：Recharts 
开发要求: 
优先检查现有项目和依赖， 复用已有组件，按需选择技术方案。保持代码简洁、结构清晰、性能良好, 并在完成后验证功能和构建。最终目标：用最少的必要代码和依赖，实现生产级的视觉效果、交互体验与工程质量。
```

**⚠️ 我的批注（重要）**：这段的技术栈是 **React + Tailwind 生态**的，
**只适用于 Nymir 和书时**。

| 项目 | 能不能用这段 |
|---|---|
| Nymir（React 19 + Vite） | ✅ 大部分适用 |
| 书时 TailTale（React 18 + Vite） | ✅ 大部分适用 |
| sonder520（零依赖原生 JS） | ❌ 全部不适用 |
| xy-intro-card（单文件零依赖） | ❌ 全部不适用 |
| 九溪（Astro + Tailwind） | ⚠️ 部分适用，但加客户端 JS 会破坏"零运行时"卖点 |
| 时念（TS + esbuild，非 React） | ❌ 不适用 |

**用之前先说清是哪个项目。** 上次我差点把这套栈套到 sonder520 上，会直接毁掉它"零依赖"的定位。

### A3｜"我不懂技术"（我描述不清时用）

```
我是一个不懂技术的小白用户，脾气还大，描述还未必清晰，我每次下得需求，不是技术的专业用语，你要先去理解我的需求，以及把我的指令变成具体的执行任务，如果你理解不了或者我的指令模糊，你可以随时停下来提问确认我的具体需求，把这个约束，规范一下
```

**我的批注**：这条对我特别有用，因为我常说"界面不够有大厂气质"这种感觉性的话，
不是技术描述。它强制 AI 先把我的感觉翻译成任务。

## B. 立项

### B1｜万能提示词：先调研，再编码

```
我要开发XXX项目先不要写代码，先去GitHub查找同类优秀开源项目。
分析它们的核心功能、架构设计以及现短板基于调研输出一套更优落地方案，等我确认方案之后，我们再动手开发
核心原则：先调研，再编码。不要让AI从零凭空造轮子，让它站在现有优秀项目的肩膀上做迭代
```

**我的批注**：这条我觉得最值。AI 默认直接给你写一个，而它写的是你第一个想到的平庸方案。
让它先看十个同类项目，出来的东西完全不一样。

---

### B2｜PRD 需求文档公式

```
原文照抄生成需求文档的万能公式提示词请输出标准产品需求文档，结构：
1.项目概述2.用户目标3.核心功能4.交互规则5.约束限制
需求：【这里填你的产品/想法】 其它要求如下: 
1这是微信小程序1.0极简版本
2不需要后端、不需要数据库、不需要注册登录
3只保留几个核心功能，尽量精简
4参考我给的图片风格(如有)，页面简洁干净。
复制时，只替换【需求】里的内容
```

**⚠️ 我的批注**：下面四条是别人做小程序时写的，**照抄会出事**。
第 1、2 条要改成我的实际情况（Web / PWA / 安卓？要不要后端？）。
第 3 条"只保留几个核心功能"值得保留——这是 1.0 的生死线。

## C. 完成前自收（收尾必用）

```
在宣布任务完成前。先按任务目标自收: 1.对需求项检查实际改动；2.查看改动文件和dift,请认没有无关修改:3.优先话行项目已有且与本次改动相关的测试，tint、类型检查或构健；4.如果本次改动引起检查失致，先定位，修复。 再重新验证:如果是既有或无关失数，明告诉我。5.没有可运行的验证方式时，不要声称"已完成"，直接告诉我末验证的部分、原因和风险，最后用短清单汇报:已完成内容，验证证据、到余风险。
```

**我的批注**：原文有错别字（dift→diff、tint→lint、构健→构建、失致→失败），
AI 能看懂，但我更建议用开源版 `04-提示词库.md` C3 的修正版。

## D. 设计品质

### D1｜Awwwards 级自检

```
以Awwwards、Webby Awards、FWA获奖级网站为品质标准，完成后从排版、留白、 视觉层级、色彩、动效、微交互、响应式和原创性上自检并持续优化，直到没有明显可提升之处。
```

**我的批注**：配合这句一起用，让它先给方案而不是直接改：
```
先逐项打分（1-10）并说明扣分在哪，我确认优先级后再改。
不要一次全改，改完一轮给我看效果。
```

```
帮我增加免费专业安全审查扫描，不着急，你先调研一下全网github开源项目，和开源skill技能以及开源技术有没有能更好的解决这些问题，更好适配我的项目。
```

### E2｜全方位代码自我审查

```
你帮我来一次高度深度详细细节仔细综合全能全面全方位代码自我审查，代码质量审查，测试覆盖与质量审查，UI/UX界面交互代码与质量审查，代码规范审查，（文档同步规范审查，全部文档是否与代码内容同步审查，文档质量审查，关于文档按需审查），全面全方位安全审查，服务器端安全审查。
```

**⚠️ 我的批注**：**别一次全跑**。七个项目一次审完产出几百条，我一个人处理不过来，
最后只会变成一份没人看的清单。建议顺序：**Nymir（风险最高）→ xy-club（有后台鉴权）→ sonder520（体量最大）→ 其余**。
而且"文档同步"这一项对我特别重要——我有七个 README 写着具体数字，一失真就违背"如实写局限"的原则。

## G. 学习与创作

### G1｜QBS 法（原文）

```
网上很火的AI高阶使用方法—QBS 法
1.把你遇到的问题发给AI让它 推荐一本出版至少30年以上的书籍
2.去Z站导出这本书的电子版PDF
3.把PDF给到任意的Agent.然后用book-to-skill指令，提炼成Skill 
4.让AI调用刚生成的Skill，去解决你的问题！
```

**我的批注**：这组提示词和我的项目天然契合——
**书时 TailTale 是阅读器，九溪有 37 本书单**。
"书 → Skill"可以考虑做成书时的一个功能方向。

### G2｜用寓言讲概念（原文）

```
请从某个领域选择一个研究生水平的概念，用寓言故事把它讲清楚。不要一开始揭晓答案,要到故事快结束时，才让人意识到原来讲的是这个概念。故事结束后，再解释概念本身，以及故事里的隐喻分别对应什么
```

**我的批注**：这条适合我理解技术概念时用。
我不懂术语，但听得懂故事——这其实就是"术语翻译"的加强版。

## H. 我的使用习惯（给自己看的）

1. **A1 几乎每次都贴**，A2 只在做界面时叠上去，A3 在我描述不清时加
2. **一次不超过 3 段**——贴多了 AI 顾此失彼
3. **听到不懂的词立刻喊停**，不要等它说完一整段
4. **C 收尾必用**——AI 说"已完成"和我确认"真完成"之间，差着这一条
5. **同一条提示词贴过三次以上，就固化进项目根目录的 AGENTS.md**
