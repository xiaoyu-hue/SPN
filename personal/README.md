# 个人补充层

> ⚠️ **如果你是别的使用者，请直接跳过整个 `personal/` 目录。**
> 根目录的 `AGENTS.md`、`SKILL.md`、`references/` 才是给你用的。

---

## 这是什么

本目录是**作者自用的一层**，放在同一个仓库里只为方便维护——一次推送、一套版本、
案例还能追溯到出处。它**不是这套规则的一部分**。

```
SPN/
├── AGENTS.md          ← 通用规则（所有人用）
├── SKILL.md
├── references/        ← 通用规则
└── personal/          ← 本目录：只有作者自己用
```

**继承关系**：`personal/AGENTS.md` 继承根目录 `AGENTS.md`，只做补充、不重写。
这正是 AGENTS.md 嵌套机制的用法——子目录只能补充，不能弱化上层强约束。

---

## 升级规则（唯一防线）

> **换个人也成立的规则，一律写到根目录的通用层，不要写在这里。**

这条不执行，两层就会功能重叠，最后变成两份互相矛盾的规则。

---

## 文件

| 文件 | 内容 |
|---|---|
| `AGENTS.md` | 个人补充规则（继承根目录，只叠加） |
| `references/01-我的项目与技术栈.md` | 我的项目、四个技术栈阵营、数字不写死的做法 |
| `references/02-我的提示词全集.md` | 我常用和别人推荐的提示词原文 + 我的批注 |
| `references/03-待办与调研清单.md` | 挂起事项与调研方向（会频繁变动） |
| `references/HANDOFF模板.md` | 跨会话交接模板 |

---

## 如果你想照着做一份自己的

1. 复制 `personal/` 整个目录，改名叫你自己的
2. `AGENTS.md` 里的【个人】条目换成你的情况
3. `references/01` 里的项目表换成你的项目、你的技术栈
4. `references/02` 里的提示词换成你实际在用的

**通用层不用动**——那部分是共享的，你只是在上面叠自己的上下文。

---

## 一个提醒

`references/03-待办与调研清单.md` 会频繁变动，**不要把它当成稳定参考**。
它存在的意义是"如实列出还没做的事"，不是"规划文档"。
