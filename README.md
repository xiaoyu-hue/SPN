# SPN · AI 协作规则（零基础版）

> **SPN = Self-precipitation（自我析出）**：在 AI 给出的众多选项里，让属于你自己的判断沉淀、成形。
> 给不懂代码、但要用 AI 把想法做成真东西的人。
> **代码是 AI 写的，判断是你做的。**

[English](./README.en.md) | 简体中文

---

## 这是什么

一套给**零编程基础者**用的 AI 协作规则。

AI 编程工具的默认行为是优化"演示能跑"。这对懂代码的人是效率提升，对不懂代码的人是风险——你无法判断它写的是不是对的、有没有偷偷扩大改动范围，而**安全边界是唯一不产生可见结果的部分**（表锁着和敞着，页面长得一模一样）。

这套规则把**判断权留在人手里**，同时不要求人懂代码。

它不是模板。每条规则都对应一类真实发生的问题。

## 快速开始

**最快：拷一份 AGENTS.md**

把根目录的 `AGENTS.md` 复制到你的项目根目录。支持 AGENTS.md 的工具（Cursor、Codex、Copilot、Gemini CLI、Aider、Windsurf 等）会在开工前自动加载它。

> ⚠️ Claude Code 在存在自身配置文件时默认不读 AGENTS.md，需要导入或配置开启。
> 稳妥做法：以 AGENTS.md 作共享基线，再给个别工具补一个薄薄的专属文件（如 `CLAUDE.md` 里写 `@AGENTS.md`）。

**按需查**

| 你在做什么 | 看哪个 |
|---|---|
| 理解判断归属、"先试再问"的判据 | `references/01-协作哲学与判断归属.md`（含英文版） |
| 要上线了 | `references/02-上线前安全自查.md`（含英文版） |
| 写 README / 选许可证 / 数字怎么不写死 | `references/03-文档、局限披露与事实维护.md` |
| 不知道怎么跟 AI 说 | `references/04-提示词库.md` |

## 这个仓库有两层

```
SPN/
├── AGENTS.md        ← 通用规则，所有人用（AI 实际加载执行）
├── SKILL.md         ← 技能入口 / 完整版说明
├── references/      ← 通用规则（4 篇，01/02 已英文化）
└── personal/        ← 作者自用的一层，⚠️ 你可以跳过
```

**`personal/` 不是这套规则的一部分**，只是作者把自用上下文放在同一个仓库里，
方便一次推送、一套版本，也让上面的案例能追溯到出处。

如果你只想用规则：**只看根目录，忽略 `personal/`**。

如果你想照着做一份自己的：复制 `personal/` 改成你的，`AGENTS.md` 继承根目录的通用规则、
只叠加你自己的上下文——通用层不用动。详见 `personal/README.md`。

## 这些规则从哪来

不是模板。每条规则背后都有一个真实判断，来自一个零基础者做出多个上线项目的过程：

| 发生过什么 | AI 做了什么 | 人的判断 |
|---|---|---|
| 第一次把项目弄上线 | 推荐了好几个静态部署平台 | 它给的是候选清单，不是命令。平台由人选定 |
| 两种视觉风格能不能融合 | 说没法保证能融合 | 想要就**直接试**——试出来成了整个项目的视觉基调 |
| 给一个加密应用划安全边界 | 顺利写出了密钥协商、签名代码 | 代码 ≠ 担保。"未经审计""不建议用于敏感场景"**由人自己写进 README** |

共同点：**AI 提供能力和方案，人负责拍板和划边界。**

完整叙事、可复用点与"先试再问 vs 先问再试"的判据，见 `references/01-协作哲学与判断归属.md`。

## 核心内容

### 三档授权（判据：撤销成本由谁承担）

- 🟢 **照做就行** — 读文件、跑测试、本地可逆改动
- 🟡 **先问再做** — 改数据库 schema、上线发布、对外动作、批量操作、Git 状态变更
- 🔴 **永远不做** — 提交密钥、密钥进前端、权限只做在前端、拼接 SQL、静默兜底、编造测试结果

### 零基础的三个关键动作

1. **术语必须先翻译，才能判断** — 不要用你听不懂的词拍板。听不懂不是你的问题，是它没讲清楚
2. **先试再问** — 判据只有一条：能不能一键还原？能就试，不能就问
3. **能力 ≠ 担保** — AI 能写出加密代码，但"未经审计"这句声明得由你来写

### 五次握手（标准工作流）

说清目标 → AI 复述验收标准 → 给方案 + 讲权衡 → 拆小步逐段交付 → 人验证 + AI 如实说明

### 重要决策：三视角分析（v1.0.0 后补入）

涉及方案选型、是否上线等重要决定时，要求 AI 从「全力反驳 → 切换支持 → 中立对比」三视角分析，而非只给一个结论。
配套「调试三步法」：描述报错 → 大白话解释原因 → 给修复步骤，禁止没定位根因就直接重写。

## 和别的 AGENTS.md 模板有什么区别

| 常见模板 | 这套规则 |
|---|---|
| 写"用什么命令、什么代码风格" | 写"谁做决定、什么时候必须停" |
| 假设使用者懂技术 | **假设使用者完全不懂技术** |
| 只写能做什么 | 一半篇幅写**不能做什么、做不到什么** |
| 给结论 | 要求 AI 讲清取舍，由人拍板 |
| 通用最佳实践 | 每条对应一类真实发生的问题 |

---

## 三条最值得记住的

1. **不要用你听不懂的词拍板。** 喊停，让它翻译成人话，再决定。
2. **能不能一键还原？** 能就试，不能就问。这一条能解决 80% 的"要不要先问"犹豫。
3. **AI 说"已完成"不等于真完成。** 用自收五条（见 AGENTS.md）卡住它。

## 已知局限（如实列出）

- 本规则针对**人不懂代码**的场景优化。专业开发者用会嫌冗余（尤其是"术语翻译""先试再问"两条），应遵循各自团队规范
- `02-上线前安全自查.md` 中的 SQL 与命令以 Supabase / Postgres 为例，Firebase、Cloudflare D1 等其他后端需自行调整
- 文中引用的安全事件与平台免费额度核实于 2026-10，会随时间变化，使用前请复核
- **本规则不能替代专业安全审计。** 涉及他人真实敏感数据（医疗、金融、身份信息）的应用，仍建议寻求专业审查
- 参考资料 `01`、`02` 已有英文版；`03`、`04` 及 `personal/` 目前仅中文，欢迎贡献翻译
