# 跨会话交接（HANDOFF）

> **AI 会话一定会失忆，这是硬限制。**
> 与其依赖工具各自的记忆功能，不如用一个 md 文件——不装插件，换工具也通用。

## 什么时候触发

**写入（会话结束前）**，出现任一信号：

- 用户说"今天先到这""这个会话要结束了"
- 单次会话改动超过 3 个文件，或上下文已经很长
- 任务卡住了，需要换时间或换人来想

**读取（新会话开始）**：

- 用户说"先读 HANDOFF.md"，或项目里存在 `HANDOFF.md` 且任务是接续的

## 写入规则

1. 写到会话**当前工作目录**的 `HANDOFF.md`（已有则覆盖，并把旧的挪到文件末尾的「历史」段，保留最近一次）
2. 不要写空话。"继续完成功能"这种等于没写——要写清楚**下一步的第一个具体动作**
3. **「失败的尝试」这一段最有价值**：不写它，下一次会重复踩同一个坑
4. 「待我拍板」里的问题要能被直接回答，不要写成需要人重新调查的问题

## 模板

```markdown
# HANDOFF

> 最后更新：YYYY-MM-DD（第 N 次交接）

## 当前任务
（一句话：在做什么，目标是什么。说不出"做完的标志是什么"，说明还没想清楚）

## 已完成
- [x] ...（含改动的文件路径 + 一行改了什么）

## 卡住的问题
（现象、已经排除的可能、怀疑的方向）

## 失败的尝试
- 试过 X，结果是 Y —— 不要再试 X

## 下一步计划
1. （第一个动作要具体到可以直接执行）
2. ...

## 踩过的坑
- ...

## 待我拍板
- （问题 + 给个倾向建议，让人一句话就能定）
```

## 读取规则

新会话读到 `HANDOFF.md` 后，第一句回报应该是：

```
已读到 HANDOFF.md：当前任务是 __，上次停在 __，下一步建议先 __。
要按这个继续吗，还是你有别的安排？
```

**不要**读完就闷头干活——先确认方向，避免在新会话里重跑一遍已经做错的分支。

## 边界

- 不要把密钥、令牌、密码写进 `HANDOFF.md`（它常常会被提交进仓库）
- 不要把整个对话历史搬进去；交接文档的价值在于**提炼**，不在于完整
