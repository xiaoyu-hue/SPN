# 协作哲学与判断归属

## 一、核心分界

```
人                            AI
提出想法            ←→        翻译术语
做出判断            ←→        提供方案
选择方案            ←→        执行实现
划定边界            ←→        写出代码
```

**代码是 AI 写的，判断是我做的。**

这条分界的意义：AI 的能力边界扩张得比你的理解快得多。如果你把判断也交出去，你会得到一个能跑、但你不知道为什么能跑、坏了也不知道怎么修的东西。

---

## 二、三个真实判断（来自作者实际项目）

### 判断一：第一次把项目弄上线
- **发生了什么**：要把本地能看的东西变成别人也能看
- **AI 做了什么**：推荐了好几个静态部署平台
- **人的判断**：它给的是候选清单，不是命令。第一个平台由人选定；免费额度用完后，自己配了备用平台
- **可复用点**：**AI 列选项，人做选择。** 选完之后"怎么配"再交回给 AI

### 判断二：两种视觉风格能不能融合
- **发生了什么**：想把喜欢的两种风格组合
- **AI 做了什么**：说没法保证能融合
- **人的判断**：想要，就直接试了。试出来真的可以，还成了整个项目的视觉基调
- **可复用点**：**"先试再问"有时比"先问再试"更顺。** 判定标准是撤销成本——改视觉几乎零成本，试一次比论证一小时快

### 判断三：给一个加密聊天应用划安全边界
- **发生了什么**：端到端加密跑通了（X25519 / HKDF / Ed25519）
- **AI 做了什么**：顺利写出了加密代码
- **人的判断**：代码不等于担保。作者不是密码学专家，所以"未经专业安全审计""不建议用于真实敏感场景"这两句话，是**人自己写进 README 的**
- **可复用点**：**能力 ≠ 担保。** AI 能做到某个程度，和你能为这个程度负责，是两件事

## 三、"先试再问" vs "先问再试"

不是非此即彼，按撤销成本分：

| 直接试（可逆、看得见结果） | 先问（不可逆或涉及他人） |
|---|---|
| 视觉风格、配色、布局 | 删文件、覆盖代码 |
| 交互手感、动效 | 数据库 schema 变更 |
| 文案、排版 | 上线发布、公开 |
| 本地小改动 | 付费、订阅服务 |
| 加一个候选方案做 A/B | 涉及他人数据的操作 |

**判据一句话：能不能一键还原？能，就试；不能，就问。**

## 四、术语翻译机制（零基础的核心外挂）

这是让不懂代码的人能做出正确判断的关键动作，不要跳过。

**流程：**
1. AI 给出一个方案，里面有一堆你听不懂的词
2. **停下，不要拍板**
3. 要求它翻译："用大白话讲，别用术语"
4. 听完再问："代价是什么？不选会怎样？还有别的方案吗？"
5. 心中确认了，才采纳

**关键心态：听不懂不是你的问题，是它没讲清楚。** 让 AI 换一种说法是它的责任。

## 五、怎么判断 AI 在糊弄你

| 信号 | 说明什么 |
|---|---|
| 只给一个方案，没有权衡 | 它没真想过替代方案 |
| 只顺着你说"好、可以"，不提示方案的代价 | 它在附和你，不是在帮你判断 |
| 满口术语，翻译后还是绕 | 它可能自己也没想清楚 |
| 说"这个很简单"但说不清代价 | 警惕 |
| 报错后立刻给兜底方案而不是查根因 | 它在掩盖问题 |
| 声称测试通过但没贴命令输出 | 要求它贴出来 |
| 提到你没见过的库 / API / 配置项 | **要求给官方文档链接，当场核实** |

最后一条最危险：**AI 会编造看起来很像真的库名和 API。** 未经核实的依赖项一律视为不存在。

**处理方式：直接追问，不要客气。** 说"我不懂"不是示弱，是给它一个必须讲清楚的信号。

## 六、工程纪律：不懂代码也要有

不懂代码不等于可以没有纪律。这四件事你不需要读代码也能要求：

1. **测试** — 改了东西要有办法确认没坏
2. **ADR（架构决策记录）** — 每次重大选型，记下"为什么选它、放弃了什么"。这是你未来的备忘录
3. **CI 门禁** — 让机器在你之前先拦一道
4. **分层架构** — 东西多了不会互相拖垮

**你要的不是理解代码，是理解"坏了怎么知道"。**

## 七、诚实是一种策略

以下是作者写进公开 README 的原话，结果反而增强了信任：

- "工具箱和读书推荐里的清单，大部分是我让 AI 帮我推荐的，我自己也没全读完"
- "时间线加进去主要是为了页面更好看"
- "未经专业安全审计""不建议用于真实敏感场景"
- "主力设备坏了，现在用备用设备更新，节奏比之前慢"
- "后台默认管理密码写在 README 里，部署上线前务必先改掉"

**规律：先说清做不到什么，别人才会信你做得到什么。**

## 八、从纯前端到全栈：身份的变化

如果你的应用数据存在用户自己浏览器里，你碰不到，也不用为它负责。

一旦加了后端和数据库，你从**工具作者**变成**数据保管人**。这是身份升级，不是难度升级。

新增的三条责任：

1. 别人的数据在你租的服务器上——你要为它的安全负责
2. 权限错误在演示里看不出来——必须主动攻击自己（见 `02-上线前安全自查.md`）
3. AI 能写出能跑的代码，但**安全边界必须由你划**
