# 文档与版本同步规范（DOC SYNC）

> 定位：代码 / CI / 功能变化后，让「文档描述」与「代码事实」保持一致的**执行清单**。
> 与「决策审查清单（DECISION_REVIEW，决策前反问）」、「决策记录 / CHANGELOG（决策后沉淀）」平级配套。
> 本模板已去除项目专属痕迹，可套用于任意项目（不限语言、不限框架）。
>
> **唯一真源原则**：
> - 版本号以**版本元数据**（如 `package.json` / `pyproject.toml` / `VERSION` / git tag）为唯一真源，其他所有文档从它派生；
> - 测试数 / 文件数等数字以**实际测试 / 构建输出**为唯一真源；
> - 功能 / 架构描述以**代码实现**为唯一真源，文档不得超出实现。

---

## 一、触发时机（任一发生即触发同步）

- [ ] 功能新增 / 修改 / 移除
- [ ] 安全或 CI 流程变化（扫描、门禁、workflow）
- [ ] 依赖变化（新增 / 移除 / 升级）
- [ ] 发版（bump 版本 + tag + Release）
- [ ] 新增文档 / 决策记录

## 二、同步清单（逐项勾选）

### A. 版本号（唯一真源：版本元数据）

| 位置 | 动作 | 校验方式 |
|------|------|---------|
| 版本元数据文件（如 `package.json` / `pyproject.toml`） | bump 版本 | — |
| 锁文件（如 `package-lock.json` / `poetry.lock`） | 同步版本 | grep |
| `CHANGELOG.md` | 新版本条目（「未发布」→正式） | grep |
| 需求 / 设计文档（如 PRD / ARCHITECTURE） | 版本头 + 状态行 + 版本历史表 | grep |
| `README.md` | 版本声明 / 徽章 | grep |
| 作者 / 项目说明文档 | 当前版本叙述 | grep |
| Release + tag | 与版本元数据一致 | 确认 |

### B. 数字与事实（唯一真源：实际输出）

| 数据 | 真源 | 需要同步的位置 |
|------|------|---------------|
| 测试数 / 测试文件数 | 测试命令输出（如 `npm test` / `pytest`） | README 表格、需求文档验收段 |
| 端到端用例数 | 端到端测试命令输出 | README、需求文档 |
| 依赖数 / 漏洞数 | 依赖 / 安全扫描输出（如 `npm audit` / `pip-audit` / OSV） | README 致谢区、安全段 |
| 依赖清单（新增 / 移除 / 升级） | 版本元数据文件 | README 致谢区 |
| 功能 / 架构描述 | 代码实现 | README、需求文档、架构文档、决策记录 |
| 分支保护 / CI 门禁 | 仓库设置 + workflow 文件 | README 安全段、CHANGELOG |
| 多语文档 | 以基准语言版为权威（改基准语言文档时必须同步其他语言版） | 各语言文档 |

### C. 文档索引

- [ ] 仓库文档索引（如 `README.md` 或 `docs/README.md`）补登新增文档
- [ ] 决策记录索引补登新增记录
- [ ] 本次改动涉及的双语 / 多语文档已同步（如无其他语言版则勾选「不适用」）

## 三、版本号规则（SemVer 判定）

| 变化类型 | 版本动作 | 例子 |
|---------|---------|------|
| 新增用户可见功能 | minor | X.Y.0 → X.(Y+1).0 |
| 修复 bug / 安全修复 | patch | X.Y.Z → X.Y.(Z+1) |
| 仅文档 / CI / 工程变更 | patch（或不 bump） | X.Y.Z → X.Y.(Z+1) |
| 破坏性变更 | major | X.0.0 → (X+1).0.0 |

**判定口诀**：用户能感知的新东西 → minor；修了错 → patch；只是整理 → patch 或不 bump。拿不准先过「决策审查清单」的决策三问。

## 四、发布前验证（必须跑）

1. **旧版本号残留检查**：`grep -rn "旧版本号" --include="*.md" --include="*.json" .` → 结果应为空，或确认命中仅为历史记录（如版本历史表、CHANGELOG 历史条目）。
2. **测试数核对**：跑全量测试，输出数字与 README 中声明一致（不一致必须修 README，不得改数字假装一致）。
3. **版本一致性**：版本元数据 = 锁文件 = CHANGELOG 最新条目 = 文档头部 = tag。
4. **CHANGELOG**：「未发布」条目已转正式；内容覆盖本次全部用户可见变更。
5. **多语对查**：本次改动涉及的各语言文档已同步；新增语言版缺失时补建或注明「不适用」。

## 五、同步检查模板（发布 PR 前填写）

```markdown
## 同步检查（DOC SYNC CHECK）

- 新版本号：____（版本元数据唯一真源）
- 测试数：____ / 测试文件数：____（实际输出）
- [ ] 版本元数据 + 锁文件一致
- [ ] CHANGELOG 已转正式
- [ ] 文档版本头已同步（需求 / 架构文档各语言版）
- [ ] README 版本声明 / 表格数字已同步
- [ ] 无旧版本号残留（grep 验证）
- [ ] 文档索引已补登
- [ ] 多语文档已同步（本次改动的语言版已更新）
- [ ] 依赖 ↔ README 致谢表一致（新增/移除依赖已反映）
- [ ] Release / tag 已创建且与版本号一致
```

## 六、与现有体系的关系

- **AGENTS.md**：引用本规范，发布前为必查项。
- **决策审查清单（`references/07-决策审查清单.md`）**：发版前先过决策三问（尤其「破坏性变更」和「版本号策略」）。
- **CHANGELOG / 决策记录（ADR）**：重大变更先记下来，再同步文档涉及的描述。
- **README / 各文档**：用户可见变更的出口，与版本号同步更新。

> 一句话：**版本号问版本元数据，数字问测试输出，描述问代码，发布前 grep 一遍再走。**
